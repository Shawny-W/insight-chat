# 记忆系统手工验收清单

本文是用户记忆功能的**手工 UI 验收清单**，覆盖短期会话上下文、长期图表偏好、指标口径映射、个人问答对、跨会话晋升、衰减、遗忘与用户隔离。它不是可执行测试：没有脚本、夹具或浏览器自动化，也不对 REST 或 UI 的自动化覆盖率作任何声明。自动化命令单独列在[第 16 节](#16-自动化检查与本清单分开)。

记忆机制的权威说明见[记忆系统](MEMORY_SYSTEM.zh-CN.md)；安装与运行期检查见[运行手册](RUNBOOK.zh-CN.md)。

## 0. 开始之前

### 0.1 前置条件

- 本地演示已初始化并已启动，在仓库根目录依次执行：

  ```bash
  python scripts/gen_retail_data.py
  python scripts/init_db.py
  python scripts/check_llm.py
  python scripts/run_server.py
  ```

  `gen_retail_data.py` 会重建演示业务库；不要对需要保留的数据执行它。
- `DEEPSEEK_API_KEY` 可用，且 `LLM_MODEL_HEAVY` / `LLM_MODEL_LIGHT` 是账号实际能调用的模型。凡是数据提问步骤都会**真实调用 LLM 并产生费用**；严格的记忆命令不会调用 LLM。
- 只运行一个服务进程。挂起的澄清与进程内上下文缓存都是进程本地的，多 worker 不会共享。
- 一个桌面浏览器。前端是单页应用，地址为 `http://127.0.0.1:8000/`。

### 0.3 你会产生的副作用

每次运行都会写入元数据库（`data/meta.db`）：

- `chat_session`、`chat_message`、`chat_context`（会话与短期上下文）；
- `query_log`、`answer`、`llm_call_log`（查询、结果快照、模型调用）；
- `user_memory`、`user_memory_event`（长期记忆及其事件历史）；
- `audit_log`（登录与记忆的 REST 操作）；
- `feedback`、`feedback_history`（👍/👎）；
- `query_exemplar`（全站共享的全局问答对，见第 10 节）。

删除是逻辑删除：遗忘一条记忆后，它的历史取值与事件仍保留用于审计。本文所有步骤都不会改动演示业务库（`test_data/data/retail.db`）。清理方式见[第 14 节](#14-清理)。

### 0.4 日期

演示数据覆盖 **2023-06-01 至 2024-06-30**。所有提问都必须使用下面写明的固定日期。“上个月”这类相对表达会按机器当前日期展开，落在演示数据范围之外，只会得到空结果。某一步返回 0 行时，先检查是不是把日期缩短了。

### 0.5 观察位置

| 观察对象 | 位置 |
|---|---|
| 意图 | 分析过程时间线第一步“意图识别 识别为 …”；展开“意图详情”可看原始事件（`question`、`rewritten`、`time_range`、`grain`、`mentions`） |
| 澄清卡 | 渲染在助手消息中，带可点击选项 |
| 假设 | 答案上方的黄色提示条 |
| 留痕 | 可折叠的“留痕核验”：SQL、SemQL、匹配解释、已应用规则、记忆使用、语义版本 |
| 记忆状态 | 顶部记忆图标，面板标题为“我的记忆” |
| 回复文本 | 下文引用的字符串都是逐字比对用的原文 |

两个有用的区分：

- 记忆命令在查询链路之前被拦截。它的意图步骤显示 `识别为 MEMORY`，回复中没有 SQL。
- 数据问题显示 `识别为 DATA_QUERY`（或其它数据意图），留痕中会出现 SQL。

### 0.6 依赖模型行为的步骤

澄清卡取决于模型是否给出歧义提及（例如 `销售额`），图表数据形态取决于生成的 SemQL。预期出现澄清卡而实际没有出现时，先把该步骤重试一次，再记为失败。不要为了“让测试通过”而接受另一种行为。

### 0.7 分节之间的重置

| 重置方式 | 效果 | 适用场景 |
|---|---|---|
| 对话命令 `忘掉全部记忆` | 逻辑删除全部长期记忆，**并**重置当前会话上下文 | 从干净状态开始一节 |
| 面板按钮“清空长期记忆” | 只逻辑删除长期记忆，会话上下文保留 | 验证两者区别（8.3） |
| 新会话（历史抽屉中的“＋ 新会话”） | 产生新的 `session_id`，长期记忆保留 | 验证跨会话行为 |

## 10. 个人问答对与共享全局问答对的区别

这是两套不同机制，不能混为一谈：

- 👍 立即为点赞用户创建**个人**问答对（`user_memory`，类别 `query_exemplar`，来源 `feedback`）。它只对该用户召回，留痕文案为 `参考了您 N 条已确认的历史问答（仅本人可见）`。
- 👍 同时计入**全站共享**的 `query_exemplar` 记录（`source='user_feedback'`）。该记录只有在 **3 个不同用户**都对同一问题的回答点赞后才会启用，之后作为全站 few-shot 示例使用。这条路径没有 UI 信号，👎 无法撤销，UI 也没有查看入口。

可选的全局路径检查（会写入共享状态）：

1. 以 `analyst` 登录，问 `2024年4月各大区的净销售额`，点击 👍。
2. 退出后以 `east_mgr` 登录，问同一问题，点击 👍。受行级策略影响，预期只有华东一行，这不影响点赞计数。
3. 退出后以 `admin` 登录，问同一问题，点击 👍。
4. 检查元数据库（使用项目 Python 环境）：

   ```bash
   python - <<'PY'
   import sqlite3
   c = sqlite3.connect("data/meta.db")
   print(c.execute("SELECT nl_question, quality_score, is_active "
                   "FROM query_exemplar WHERE source = 'user_feedback'").fetchall())
   PY
   ```

   预期：该问题只有一行，`quality_score = 3`、`is_active = 1`。

这条共享记录无法通过 UI 或 API 删除，见[第 14 节](#14-清理)。

## 12. 记忆命令的边界情况

### 12.1 缺少数据场景

```text
以后都用折线图
```

预期：`请说明偏好的数据场景，例如「以后趋势都用折线图」或「以后分类对比都用柱状图」。` 不保存任何内容，也不会降级成数据查询。

### 12.2 不存在的指标

```text
记住销售额指不存在的指标
```

预期：`找不到唯一指标「不存在的指标」，请使用完整指标名，例如「净销售额」。` 不保存任何内容。

### 12.3 以“以后 / 今后”开头的普通问题

```text
以后 2024年3月到5月每月净销售额
```

```text
今后 2024年4月各大区的净销售额
```

预期：两者都不会被识别为记忆命令——意图步骤显示的不是 `MEMORY`——并按数据问题继续处理。查询本身能否成功取决于模型；这一步要验证的是“以后 / 今后”前缀没有被劫持成记忆命令。

### 12.4 当次图型指定不是记忆命令

```text
2024年3月到5月每月净销售额，用柱状图展示
```

预期：意图不是 `MEMORY`；按数据问题执行，当次使用柱状图，且不写入长期记忆。

## 13. 记忆面板与展示上限

在存在若干条记忆时，打开面板检查：

- 每行显示内容、来源（`明确指定`、`切图学习`、`澄清学习`、`点赞确认`）、状态、有效置信度与使用次数；
- 候选记忆显示 `待跨会话确认`；
- 刚晋升的澄清映射显示 `生效中`，而不是 `待跨会话确认`；
- 删除单条只删除目标行，其余保留；
- “清空长期记忆”会先确认，然后进入空态；
- 没有记忆时显示空态提示；
- 接口失败时（例如停掉服务后打开面板）显示读取失败与“重试”按钮；重启服务后点击“重试”，列表恢复。

UI 已实现的边界：

- 没有编辑功能。要修改偏好，重新下一条命令即可；新值会取代旧值，旧值从当前列表消失但仍保留在历史中。
- 没有历史视图。被取代或删除的记录只能通过 `GET /memories?include_history=true` 获取。
- 口径映射行显示原始 `term_id`（例如 `「销售额」→「term_net_sales」`），而对话中的列表命令会解析成中文名。
- 对话列表命令最多展示 10 条语义记忆；面板展示全部。
- `已衰减 · 不生效` 是“生效中但有效置信度低于下限”的展示规则。按默认半衰期（明确记忆 365 天，学习类 90 天），单次测试内到不了这个状态；不要把它列成快速通过项。
- 图表切换复用已保存的答案快照，快照最多包含**前 200 行**。原结果行数更多时，切换后的图会被标记为截断。演示中的聚合结果远低于该上限，所以把这当作已知边界，而不是可操作步骤。

## 14. 清理

1. 对用过的每个账号（`analyst`、`east_mgr`、`admin`）登录后执行 `忘掉全部记忆`，或在面板点击“清空长期记忆”。这是逻辑删除，记录与事件仍留在元数据库中用于审计。
2. 会话与消息无法从 UI 删除。确实需要时，可对每个会话调用 `DELETE /api/v1/chat/sessions/{id}`，或按下一步重置元数据库。
3. 需要回到全新演示状态时：停止服务，删除 `data/meta.db`，重新执行 `python scripts/init_db.py`，再启动服务。

   这会清空**所有**用户的记忆、会话、反馈、审计记录与全局问答对，并重新发布种子快照 v1。不要对需要保留内容的数据库执行。演示业务库不受影响。

## 15. 验收清单

| 能力 | 通过标志 |
|---|---|
| 对话切图 | 意图为 `MEMORY`，不重新查询，SQL 不变，图表切换 |
| 长期图表偏好 | 新会话同族查询沿用偏好；其他用户不继承 |
| 当次图型指定 | 仅当次生效，带 `未写入长期偏好` |
| 否定表达 | 被否定的图型不会被强制；不出现错误的“按您当次要求” |
| 长期口径 | 不再重复澄清；SemQL 使用所选指标 |
| 澄清晋升 | 3 个不同会话后晋升；同会话重复不计数 |
| 重启恢复 | 同一页面重启后已完成上下文可恢复；挂起卡片不可 |
| 面板清空与对话清空 | 面板只清长期记忆；`忘掉全部记忆` 同时重置会话上下文 |
| 个人问答对 | 点赞后召回，点踩后撤销，按用户隔离 |
| 全局问答对路径 | 3 个不同用户点赞后才启用；无 UI 信号；不可删除 |
| 用户隔离 | `east_mgr` 不继承 `analyst` 的任何记忆 |
| 记忆命令 | 未知指标、缺少场景均按提示拒绝，且不保存 |
| 防误判 | 普通“以后 / 今后”问题与名词“表格”不被劫持 |
| 记忆面板 | 列表、逐条删除、清空、空态、错误态；无编辑、无历史 |

## 16. 自动化检查（与本清单分开）

```bash
# Memory unit tests (isolated in-memory SQLite; the second file loads the real seeded snapshot)
python -m pytest tests/test_memory.py tests/test_clarify_memory.py -q

# Whole suite
python -m pytest tests/ -q

# Compilation, policies, and execution without LLM calls
python scripts/dev_query.py
```

前置条件与覆盖范围：

- 单元测试**不调用 LLM**，但项目导入需要 `.env` 中的 `DEEPSEEK_API_KEY`；`tests/test_clarify_memory.py` 还需要已初始化且含已发布快照的元数据库。
- 测试套件覆盖（节选）：图表偏好的应用与按用户隔离、数据形态与可选类型限制、当次指定与否定表达、基于快照的图表切换、软取代与软删除、事件、访问不续期的衰减、跨会话晋升、会话与长期偏好的优先级、上下文往返/过期/损坏/归属、通过清缓存模拟重启、LRU 对待澄清会话的保护、澄清归属与伪造选项、个人问答对召回与隔离、按类别清空、严格命令解析、自定义时间兜底。
- 未覆盖：REST 路由、UI、`audit_log`、👍 到个人问答对的集成、对话命令的列表/遗忘路径、针对 `data/meta.db` 的真实重启、`include_history`、422 校验行为、真实 LLM/SSE 流程。
- `scripts/` 下没有驱动记忆场景的脚本，也没有浏览器自动化。`scripts/run_pipeline_test.py` 会真实调用模型，但不对记忆行为做断言。

把自动化检查当作确定性内核的回归门禁，把本清单当作真实用户可见的端到端行为验收。
