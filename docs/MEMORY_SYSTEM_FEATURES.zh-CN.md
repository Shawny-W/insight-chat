# 记忆系统：功能特性与设计亮点

InsightChat 只记住一小部分明确的信息：当前会话在聊什么、用户偏好哪种图表与指标口径、以及用户确认过哪些问题/SemQL 对。本文是面向用户与评审者的简要导览。权威行为、API、存储模型与完整边界清单见[记忆系统](MEMORY_SYSTEM.zh-CN.md)；页面级手工验收见[记忆系统手工验收清单](MEMORY_SYSTEM_TEST_SCRIPTS.zh-CN.md)。

## 能力速览

| 用户可以做什么 | 系统会做什么 |
|---|---|
| 追问“那华北呢” | 复用本次会话最近的指标、时间范围与过滤条件 |
| 说“以后趋势都用折线图” | 只记住趋势这一数据形态的图表偏好 |
| 在回答上点击另一种图型 | 重绘已存结果快照，并学习该偏好 |
| 在某个问题里说“用柱状图” | 仅本次生效，不形成长期偏好 |
| 多次确认同一个歧义术语 | 在三个不同会话后晋升为长期映射 |
| 给好回答点赞 | 把该问题与 SemQL 加入个人示例 |
| 打开“我的记忆” | 查看、删除或清空本人的长期记忆 |

它的目标不是模拟用户画像，而是减少重复的 BI 工作，同时保持每个回答可核验、每次数据访问不变。

## 用户可以感知的功能

### 1. 追问不必重复表述

问过“2024年4月各大区的净销售额”后，继续说“那华北呢”可以继承指标与时间范围。会话保留最近最多五轮，用于指代改写、意图识别与生成。

### 2. 按数据场景记忆图表偏好

偏好按数据形态保存——趋势、分类对比、占比、单指标、明细或其他——而不是设置一个全局图型。“趋势用折线图”不会把所有饼图都变成折线图。只有目标图型仍在规则引擎为该回答允许的图型集合内时，偏好才会生效。

### 3. 切图不重新查数

在回答上切换图型会复用已存的列与行，不重新生成 SemQL，也不执行 SQL，因此纯粹的展示调整不会改变数字。由于快照最多保存 200 行，原始结果更大时，切换后会明确标记为截断。

### 4. 当次要求不会变成长期偏好

在问题里加上“用柱状图”只影响当前回答；“以后分类对比都用柱状图”才会形成长期偏好。“不要用折线图”这类否定表达不会被当成要求，普通文本里出现的“表格”也不会被当成图表命令。

### 5. 口径选择可以跨会话学习

在澄清卡上选择“净销售额”会立即解决当前会话的问题。同一选择在三个不同会话出现后晋升为长期映射，后续会话不再重复询问。同一会话内重复点击不累计。晋升之前，候选不会在该会话之外生效。

### 6. 个人已确认问答作为示例

对成功的数据回答点 👍，会把问题与 SemQL 保存为个人示例。后续相似问题可以把它作为 few-shot 示例召回，回答会说明使用了个人历史问答。点 👎 会撤销该示例。召回基于字面重合度而非向量相似度，且合并后最多使用三条。

### 7. 置信度会衰减，且不能自我续期

长期记忆从最后确认时间开始衰减。使用记忆只更新使用统计，不延长它的寿命。低于配置的置信度阈值后，生效中的记忆不再被应用，但仍会在面板中显示为已衰减。再次重复或明确表达该偏好会刷新它。

### 8. 可控、可见、相互隔离

记忆面板展示每条记录的内容、来源、状态、有效置信度与使用次数，支持逐条删除与全部清空。记忆按 `user_id` 隔离：一个用户的偏好不会影响另一个用户的回答。回答还会附带简短的记忆留痕，说明应用了哪条偏好或示例。

## 设计亮点

### 1. 面向 BI 的记忆对象

长期层只存图表偏好、指标术语映射和个人问题/SemQL 对。没有通用事实记忆、没有过程性记忆，也没有跨用户或部门的图表/术语偏好共享。被点赞的问题仍可能进入共享示例池（见“需要了解的边界”）。正是这种窄范围让确定性写入与可预测消费成为可能。

### 2. 由数据形态决定偏好是否适用

系统根据编译后的列角色与 SemQL 推导数据形态，再查找该形态的偏好。保存的“折线图偏好”不会被强加到分类对比上；不兼容的偏好会被忽略，而不是画出误导性的图表。

### 3. 澄清学习采取保守门槛

澄清选择可以立即改善当前体验，但只有跨会话一致重复后才会固化。这个门槛是刻意的：一次含糊的点击应当改善当前会话，而不是悄悄改变未来的回答。候选以较低置信度保存，且永远不会被消费。

### 4. 衰减锚定确认时间，而不是使用时间

衰减公式使用 `last_confirmed_at`。应用偏好会增加 `access_count` 与 `last_accessed_at`，但从不触碰锚点。因此，一条被频繁使用却长期未确认的偏好会如实老去，而一次新的确认就能恢复它。

### 5. 软取代而非覆盖

偏好变化时，旧版本被标记为失效并写入结束时间，同时插入新的当前版本。删除也是逻辑操作。当前状态保持简单，历史仍可通过 API 审计。

### 6. 确定性、轻量、无新增依赖

写入来自严格命令模式、澄清选择、图表切换与反馈。召回基于规则化字符重合度叠加有效置信度。没有向量库、没有嵌入调用、没有额外的 LLM 抽取、也没有新增 Python 包，因此行为可复现、可测试。

### 7. 只降级，不阻断

偏好读取失败时，使用规则引擎图表或正常澄清卡；个人示例召回失败时，使用共享示例；记忆命令失败时，返回说明文本而不是破坏数据查询。记忆是增强层，不是主链路的依赖。

### 8. 每一步都校验属主并留下痕迹

会话、记忆、挂起澄清与图表切换都会校验属主。REST 层从 token 推导用户，客户端无法为他人写记忆，也无法伪造来源或置信度。留痕与记忆面板让已应用的偏好可见，回答快照让图表切换可复现。

## 记忆刻意不做的事

- 不记住任意的聊天事实或用户操作习惯。
- 不做嵌入或向量相似度召回。
- 不把一个用户的图表或术语偏好共享给另一个用户。
- 不执行 SQL，不绕过 SQL 网关，不改变行/列权限。
- 不让候选偏好在晋升前生效。
- 不物理擦除已删除或被取代的值；“忘掉”是逻辑操作。
- 切换图表时不重新查询数据。

## 试一试

```text
2024年3月到5月每月净销售额
换成柱状图
以后趋势都用折线图
记住销售额指净销售额
你记得我什么
忘掉销售额口径
忘掉全部记忆
```

这些命令覆盖了记忆的写入、使用、查看与遗忘。图表偏好也可以在任何数据回答的图表工具栏中修改。

## 需要了解的边界

- 会话上下文与挂起澄清位于单个进程。挂起澄清不跨重启，已完成的上下文可以恢复。
- 浏览器刷新会丢失当前 `sessionId`；服务端可能仍有上下文，但界面不会重建对话。
- 界面清空按钮只清空长期记忆。对话命令 `忘掉全部记忆` 还会重置当前会话上下文。
- 图表切换最多渲染回答中保存的 200 行。
- 记忆接口只要求登录，不要求特定角色；管理员没有跨用户记忆视图。
- 对话记忆命令会记录为记忆事件，但不进入安全审计日志。
- 被点赞的问题在三个不同用户点赞后仍可能晋升到共享示例池，尽管个人记忆记录保持私有。
- 记忆面板没有编辑与历史视图；修改需要发出新命令，历史只能通过 API 获取。
