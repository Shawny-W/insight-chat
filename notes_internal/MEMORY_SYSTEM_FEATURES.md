# InsightChat 记忆系统功能特性与创新点

> 本文基于当前项目实现与 `MEMORY_SYSTEM_TEST_SCRIPTS.md` 的可测试功能整理，只描述已经落地的能力。

## 一、核心功能特性

### 1. 短期会话记忆

系统保存最近对话轮次、上一轮 SemQL、已澄清选择和最近回答。用户追问“那华北呢”时，可以继承前文的时间、指标和口径，不必重复表达。

### 2. 会话状态跨重启恢复

短期上下文同时写入 SQLite，并使用进程内 LRU 加速。服务重启后，已完成的会话上下文仍可恢复，追问不会因进程退出而失效。

### 3. 用户级长期记忆

长期记忆按 `user_id` 隔离。一个用户的图表偏好、指标口径和个人问答对，不会影响其他用户。

### 4. 分场景图表偏好

系统按趋势分析、分类对比、占比分析等数据形态记忆图表偏好，而不是简单设置一个全局图型。用户可以只让趋势查询默认使用折线图，其他场景继续使用原推荐规则。

### 5. 对话式切图

用户可以直接说“换成柱状图”或“生成折线图”。系统切换当前回答的图表，并记住该数据场景下的偏好。

### 6. 切图不重新查数

图表切换复用原回答的结果快照，不重新生成或执行 SQL。切换速度更快，也避免同一数据因重复查询产生口径变化。

### 7. 图型兼容性校验

图表偏好只能在原规则引擎允许的图表类型内生效。当前数据不支持目标图型时，系统明确提示，不强行生成不合适的图表。

### 8. 当次指定与长期偏好分离

“本次用柱状图展示”只影响当前查询；“以后趋势都用柱状图”才写入长期记忆。用户的一次性要求不会意外变成永久偏好。

### 9. 长期指标口径记忆

用户可以明确指定“销售额指净销售额”。后续新会话遇到同一歧义时，系统自动沿用该口径，不再重复弹出净/毛销售额澄清卡。

### 10. 澄清选择自动学习

同一术语在三个不同会话中被一致澄清后，系统会将候选选择晋升为长期偏好。同一会话内重复选择不会累计晋升次数。

### 11. 多层级记忆优先级

系统按“当次明确要求 → 当前会话选择 → 有效长期偏好 → 全局默认”处理冲突。用户当前的明确表达始终优先。

### 12. 失效记忆安全回退

长期记忆中的术语或选项如果已经不在当前语义版本候选集合内，系统不会强行使用，而是恢复原有澄清流程。

### 13. 个人问答对记忆

用户点赞成功回答后，系统将对应的问题与 SemQL 保存为个人问答对，并在后续相似问题中作为 few-shot 示例参考。

### 14. 点踩撤销个人问答对

用户点踩后，对应个人问答对会被撤销，不再参与后续召回。个人内容不会因点赞机制直接进入其他用户的记忆。

### 15. 时间衰减与遗忘

长期记忆根据未再次确认的时间进行指数衰减。有效置信度低于阈值后停止生效，但记录仍保留，便于审计和恢复。

### 16. 用户主动清除记忆

用户可以按类别忘掉图表偏好、问答记忆或指定术语口径，也可以一键清空全部长期记忆和当前会话上下文。

### 17. 记忆可视化管理

右上角“我的记忆”展示记忆内容、来源、有效置信度、使用次数和当前状态，支持逐条删除与全部清空。

### 18. 记忆使用留痕

每次实际沿用长期口径、图表偏好或个人问答对时，结果都会记录到 `memory_trace`。用户可以核验系统为什么采用当前口径或图表。

## 二、设计与工程创新点

### 1. BI 语义感知的记忆模型

记忆对象不是泛化的聊天事实，而是“用户 + 数据场景 + 图表类型”或“用户 + 业务说法 + 指标术语”。记忆可以直接参与 BI 查询链路，而不是只用于聊天寒暄。

### 2. 图表偏好与数据形态绑定

系统根据 `columns_meta` 和 SemQL 判断数据形态，再决定是否应用偏好。同一个“折线图偏好”不会被错误套用到所有查询。

### 3. 澄清记忆与长期偏好贯通

一次澄清先解决当前会话的连续追问，多次跨会话一致选择再固化为长期口径。兼顾了即时体验和长期学习的稳健性。

### 4. 防止旧记忆自我续期

衰减依据是最后确认时间，而不是最后使用时间。系统反复应用旧记忆只会增加访问统计，不会让旧记忆永远保持有效。

### 5. 软失效代替直接覆盖

新偏好取代旧偏好时，旧版本标记为失效并保留有效时间区间。偏好如何变化、何时变化均有历史可查。

### 6. 记忆与权限边界分离

记忆只影响展示和语义选择，不绕过 SQL 网关、行级权限、列级权限或查询限额。图表快照也只允许本人访问。

### 7. 严格命令识别避免误学习

普通“以后/今后”开头的问题仍按数据查询处理；“不要用折线图”等否定表达不会被识别成正向偏好；普通文本中的“表格”不会自动触发展示命令。

### 8. 记忆故障不影响主查询

记忆读取或写入异常时，数据查询自动回退到原有澄清、全局示例和图表推荐规则。记忆是增强能力，不是主链路的单点依赖。

### 9. 个人学习与全局治理分离

个人点赞先形成私有问答对；原有全局 exemplar 仍按多用户确认机制治理。兼顾个性化与公共知识的准入控制。

### 10. 轻量级确定性实现

系统只使用现有 SQLite 和确定性规则，不新增向量库、知识图谱或额外 LLM 抽取。部署成本不变，记忆行为可以稳定复现和测试。

### 11. 并发与异常状态防护

当前记忆写入使用事务保护，防止并发产生多个有效版本；上下文加载处理损坏 JSON、过期数据、越权访问和缓存淘汰。

### 12. 可验证的完整闭环

每项核心能力都有对应的问题脚本：写入、使用、跨会话继承、用户隔离、失效、撤销、重启恢复和异常分支均可通过真实页面验收。

## 三、用户可感知的使用方式

```text
以后趋势都用折线图
记住销售额指净销售额
换成柱状图
你记得我什么
忘掉销售额口径
忘掉全部记忆
```

这些命令覆盖了记忆的新增、使用、查看和遗忘，形成完整且可逆的用户体验。
